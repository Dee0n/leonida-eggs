# AGENTS.md — инструкция для нейросетей-редакторов

Ты редактируешь проект **«ЛЕОНИДА — листок пасхалок»**: дополняемый набор подсказок по GTA VI
в стиле старых листков с чит-кодами. Твоя работа — добавлять и уточнять записи, не ломая формат
и не раскрывая спойлеров.

## 1. Границы (жёстко)

- **Никаких спойлеров.** Запрещено описывать, что игрок увидит, получит или чем всё кончится.
- **Не выдумывай.** Если источника нет — запись идёт как `rumor`, а не «наверное, там».
- **Не трогай `out/` и `docs/` руками** — это сгенерированные файлы, они перезаписываются сборкой.
- **Не меняй `data/schema.json`** без необходимости; если меняешь — обнови `README.md` и этот файл.

## 2. Карта проекта

```
data/entries.json   — единственный источник правды
data/schema.json    — схема (справочно, сборка проверяет поля сама)
tools/build.py      — check / build / site / new, стандартная библиотека Python 3.10+
out/                — локальная сборка с картинками, генерируется, в git не входит
docs/               — публичная версия для GitHub Pages (`build.py site`), генерируется
images/             — скрины для личной печати, в git не входят
README.md           — инструкция для людей
AGENTS.md           — этот файл
```

## 3. Формат записи

```json
{
  "id": "kebab-case-slug",
  "section": "city",
  "title": "Нейтральное название, до 80 символов",
  "hint": "Куда идти и что нажать. До 400 символов.",
  "confidence": "single",
  "sources": [{ "name": "Издание", "url": "https://..." }],
  "added": "2026-11-24",
  "added_by": "имя-агента"
}
```

Поля:

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | уникальный, `[a-z0-9-]`, отражает суть, не номер |
| `section` | да | один из id в `sections` (`keys`, `city`, `north`, `water`, `phone`) |
| `title` | да | до 80 символов, без спойлера, без нумерации |
| `hint` | да | до 400 символов, только путь и действие |
| `confidence` | да | `confirmed` \| `single` \| `rumor` |
| `sources` | да | массив `{name, url}`; для `confirmed` — минимум 2 |
| `added` | да | `YYYY-MM-DD` |
| `added_by` | да | кто добавил |
| `image` | нет | `images/<id>.jpg`: скрин карты с меткой или ориентира. Только место, без кадра с самим событием. Если на картинке две половины (карта + событие), оставь половину с картой. Скачанный файл клади в `images/`. |
| `image_source` | при `image` | `{name, url}`: откуда скрин. Без него картинка не попадёт на публичный сайт, а под картинкой печатается «Скрин: name». |
| `kind` | нет | `egg` (по умолчанию) — пасхалка, где надо что-то сделать; `poi` — точка интереса: прийти и посмотреть. Точки интереса идут в конце раздела под своим подзаголовком. |
| `note` | нет | служебная пометка, в листок не попадает |

Нумерация **не хранится**: сборка считает её по порядку секций и записей. Поэтому вставлять запись
можно в любое место массива — номер пересчитается.

## 4. Алгоритм добавления

1. Прочитай `data/entries.json`.
2. Проверь дубликаты: поиск по `title` и по ключевым словам `hint`. Если запись уже есть — уточняй её,
   а не плоди новую.
3. Выбери секцию:
   - `keys` — Leonida Keys;
   - `city` — Vice City и пригороды;
   - `north` — север штата, болота, глубинка;
   - `water` — море, берег, острова;
   - `phone` — телефон, радио, журналы, приложения;
   - `controls` — неочевидные кнопки: в `title` комбинация и где жать, в `hint` что делает (здесь это не спойлер);
   - слухи без точного места не добавляй; слух с местом — в подходящую секцию с `confidence: rumor`.
4. Сформулируй `hint` по стайлгайду (раздел 5).
5. Проставь `confidence` по правилам раздела 6 и заполни `sources`.
6. Вставь объект в `entries`.
7. Запусти:

```powershell
python tools\build.py check
python tools\build.py build
python tools\build.py site
```

8. Если `check` даёт ошибки — исправь и повтори. Предупреждения разбери, но они не блокируют сборку.
9. Проверь, что `out/leonida_easter_eggs_<issue>.html` открывается и запись стоит на месте.

## 5. Стайлгайд подсказок

Это листок с кодами, а не загадка. Человек читает строку и сразу знает, куда ехать и что делать.
Формат: **место по карте** (округ, район, улица, ориентир) → **условия** (глава, время суток, погода) →
**действие** (что нажать, куда залезть, какой код ввести). Коды, пароли и комбинации кнопок пиши всегда.
Не пишешь только то, что там окажется.

`title` у пасхалки (`kind` не указан или `egg`) — нейтральное название места или предмета, по нему не должно быть понятно, что там.

`title` у точки интереса (`kind: poi`) — место и прямо названная отсылка: «Квартира Декстера Моргана: Trinity Apartments», «Рингтон Wind Chimes: телефон Майкла из GTA V». Там нечего разгадывать, без названия отсылки строка бесполезна. Если в точке есть задание, награда или цепочка действий — это не `poi`, а пасхалка с нейтральным названием.

**Хорошо:**

- «Округ Леонард, юго-западнее Белвилла. Заходи через гараж. Ближе всего после глав 2–3.»
- «Округ Саут-Вайс-Дейл, самая высокая вышка к северу от Хамлета. Лезть минут семь. Наверху: △/Y взять, L2 + R2 бросить.»
- «Пеликан-Вэлли, болота Грассриверс. Сейф: 00072. Лодочный сарай: 0212.»

**Плохо:**

- «Ночь, туман, берег. Корабль, которого там быть не должно.» — нет места, нет действия, это загадка.
- «Точка не фиксированная. Лучше ночью и лучше одному.» — найти по этому нельзя.
- «Внутри ты найдёшь костюм Томми Версетти и его мотоцикл.» — раскрыто содержимое.
- «Легендарная пасхалка №1.» — оценка вместо инструкции.

Нет точного места в источниках — не добавляй запись, пока оно не появится.

Требования к языку: русский, повелительное наклонение, короткие фразы, как пишет живой человек на форуме, а не справочник. Без длинных тире (ставь обычный дефис или точку), без эмодзи, без CAPS,
без оценочных прилагательных («крутая», «легендарная»).

## 6. Достоверность

- `confirmed` — **два независимых источника** (разные издания / разные авторы). Один пересказ другого
  за два источника не считается.
- `single` — один источник: репортаж, тред, видео. Ставится по умолчанию для новых находок.
- `rumor` — слух, «говорят», единичное сообщение без деталей.

Повышать `single` → `confirmed` можно только при появлении второго независимого источника.
Понижать — можно всегда, если источник отпал; укажи причину в `note`.

## 7. Дедупликация

Перед добавлением проверь:

- точное совпадение `title`;
- совпадение места в `hint` (одна локация — одна запись, если это не разные шаги одной цепочки);
- цепочки (например, «радиовышка → подстанции → SMS → портал») оформляются как отдельные записи
  с `id` вида `tommy-tower`, `tommy-substations`, `tommy-sms`, `tommy-portal`.

Если запись уточняет существующую — правь существующую, а не создавай вторую.

## 8. Определение готовности (DoD)

Задача считается выполненной, когда:

- [ ] `python tools\build.py check` завершился без ошибок;
- [ ] `python tools\build.py build` собрал оба файла;
- [ ] `python tools\build.py site` обновил `docs/`;
- [ ] `python -m unittest discover -s tests` проходит;
- [ ] в листке появилась ровно одна новая запись (или изменена ровно одна существующая);
- [ ] `hint` не содержит слов из списка спойлеров и не описывает награду;
- [ ] `confidence` соответствует числу источников;
- [ ] `id` уникален и не содержит номера;
- [ ] в `out/` нет ручных правок.

## 9. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `неизвестная секция` | опечатка в `section` | сверить с `sections` в `entries.json` |
| `повторяется id` | скопировали запись | новый `id` |
| `confirmed требует минимум 2 источника` | один источник | поставить `single` |
| `в hint слово «награда»` | описание результата | переписать как маршрут |
| запись не появилась | секция `checklist` | записи идут только в секции без `type` |

## 10. Выпуски

`meta.issue` — номер листка. Новый выпуск: увеличить номер, обновить `meta.date`, собрать.
Старые файлы в `out/` не удалять — они остаются историей.
